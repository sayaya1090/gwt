# GWT Gradle Plugin Requirements

이 문서는 `gwt` 플러그인이 충족해야 하는 주요 기능 및 비기능 요구사항을 정의합니다.

## 1. 기능 요구사항 (Functional Requirements)

### 1.1 GWT-Lombok 통합
- **FR1**: GWT 컴파일러가 Lombok 어노테이션이 적용된 소스 코드를 올바르게 인식하고 처리할 수 있도록 개발 환경을 자동 구성해야 한다.
- **FR2**: 사용자가 별도의 복잡한 어노테이션 프로세서 설정 없이 플러그인 적용만으로 Lombok을 사용할 수 있어야 한다.

### 1.2 테스트 환경 자동화
- **FR3**: 각 GWT 모듈에 대해 테스트에 필요한 HTML 호스트 파일을 자동으로 생성해야 한다.
- **FR4**: 메인 소스와 테스트 소스를 통합하여 GWT 테스트 모듈을 컴파일하는 전용 태스크(`gwtTestCompile`)를 제공해야 한다.
- **FR5**: 표준 `test` 태스크 실행 시 GWT 컴파일 및 HTML 생성이 선행되도록 의존성을 자동 구성해야 한다.

### 1.3 테스트 서버 인프라
- **FR6**: GWT 컴파일 결과물(JS, HTML, 리소스)을 브라우저에 서빙할 수 있는 내장 웹 서버를 제공해야 한다.
- **FR7**: 웹 서버는 동적 포트 할당을 지원하여 포트 충돌을 방지해야 한다.
- **FR8**: 빌드 라이프사이클과 연동되어 테스트 시작 전 자동으로 서버를 시작하고, 빌드 종료 시 안전하게 종료해야 한다.

### 1.4 브라우저 기반 검증 (Testing SDK)
- **FR9**: Kotest 프레임워크 위에서 Playwright를 이용해 브라우저를 제어할 수 있는 베이스 클래스(`GwtTestSpec`)를 제공해야 한다.
- **FR10**: 브라우저 콘솔 로그를 실시간으로 캡처하여 테스트 코드 내에서 검증(`shouldContainLog`)할 수 있는 기능을 제공해야 한다.

## 2. 비기능 요구사항 (Non-Functional Requirements)

### 2.1 효율성 및 성능
- **NFR1 (공유 서비스)**: 멀티 모듈 프로젝트나 병렬 테스트 실행 시에도 하나의 웹 서버 인스턴스를 공유하여 메모리 및 CPU 리소스 낭비를 최소화해야 한다.
- **NFR2 (캐싱)**: GWT 컴파일 태스크는 Gradle의 Build Cache를 지원하여 변경 사항이 없을 경우 재실행되지 않아야 한다.

### 2.2 사용성
- **NFR3 (기본 설정 제공)**: 최소한의 설정(Convention over Configuration)으로 동작해야 하며, 필요한 경우 사용자가 설정을 오버라이드할 수 있어야 한다.
- **NFR4 (가독성)**: 테스트 실패 시 브라우저 로그와 에러 메시지를 명확하게 노출하여 원인 파악이 용이해야 한다.

### 2.3 안정성 및 호환성
- **NFR5**: Gradle의 최신 버전(8.x 이상) 및 Java 11 이상의 환경에서 안정적으로 동작해야 한다.
- **NFR6**: 기존 `org.docstr.gwt` 플러그인과 호환되어야 하며, 이를 확장하는 방식으로 동작해야 한다.
